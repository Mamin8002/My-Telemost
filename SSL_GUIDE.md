# 📜 Пошаговая инструкция по созданию SSL сертификата

Это руководство поможет вам создать самоподписанный SSL сертификат для MeetFlow вручную.

## 📋 Что вам понадобится

- **OpenSSL** — утилита для работы с SSL/TLS сертификатами
- **Терминал** (Linux/macOS) или **Command Prompt** (Windows)
- **IP адрес вашего сервера** (например, `192.168.1.100`)

---

### macOS

## 🔐 Шаг 3: Генерация приватного ключа

Приватный ключ — это основа вашего сертификата. **Никому не передавайте этот файл!**

### Linux/macOS

```bash
openssl genrsa -out server.key 2048
```

### Windows

```cmd
openssl genrsa -out server.key 2048
```

**Что происходит:**
- `genrsa` — генерирует RSA ключ
- `-out server.key` — сохраняет в файл `server.key`
- `2048` — длина ключа в битах (рекомендуется 2048 или 4096)

**Ожидаемый результат:**
```
Generating RSA private key, 2048 bit long modulus
.....................................................................................................................+++
.......................+++
e is 65537 (0x10001)
```

**Проверьте файл:**
```bash
ls -lh server.key
# -rw-r--r-- 1 user user 1.7K ... server.key
```

## 📝 Шаг 4: Создание конфигурационного файла

Конфигурационный файл нужен для указания параметров сертификата, включая **SAN** (Subject Alternative Names) — дополнительные имена и IP адреса.

### Linux/macOS

Создайте файл `openssl.cnf`:

```bash
nano openssl.cnf
```

Или используйте любой текстовый редактор:

```bash
# Используя vim
vim openssl.cnf

# Используя VS Code
code openssl.cnf
```

### Windows

Создайте файл `openssl.cnf` с помощью Блокнота:

```cmd
notepad openssl.cnf
```

### Содержимое конфигурационного файла

Скопируйте и вставьте следующий текст, **заменив `192.168.1.100` на ваш IP адрес**:

```ini
[req]
default_bits = 2048
prompt = no
default_md = sha256
req_extensions = req_ext
distinguished_name = dn

[dn]
C = RU
ST = Moscow
L = Moscow
O = MeetFlow
OU = Development
CN = 192.168.1.100

[req_ext]
subjectAltName = @alt_names

[alt_names]
DNS.1 = localhost
DNS.2 = *.local
IP.1 = 127.0.0.1
IP.2 = 192.168.1.100
```

**⚠️ ВАЖНО:** Замените `192.168.1.100` на реальный IP адрес вашего сервера!

**Как узнать IP адрес:**

Linux/macOS:
```bash
# Вариант 1
hostname -I | awk '{print $1}'

# Вариант 2
ip addr show | grep "inet " | grep -v 127.0.0.1

# Вариант 3 (macOS)
ipconfig getifaddr en0
```

Windows:
```cmd
ipconfig | findstr /i "IPv4"
```

**Сохраните файл:**
- **nano:** `Ctrl+O`, затем `Enter`, затем `Ctrl+X`
- **vim:** `:wq` и `Enter`
- **Блокнот:** `Ctrl+S`

## 📜 Шаг 5: Генерация SSL сертификата

Теперь создайте самоподписанный сертификат на основе ключа и конфигурации.

### Linux/macOS

```bash
openssl req -new -x509 -key server.key -out server.crt -days 365 -config openssl.cnf -extensions req_ext
```

### Windows

```cmd
openssl req -new -x509 -key server.key -out server.crt -days 365 -config openssl.cnf -extensions req_ext
```

**Что происходит:**
- `req` — команда для работы с сертификатами
- `-new` — создает новый запрос
- `-x509` — создает самоподписанный сертификат (не CSR)
- `-key server.key` — использует приватный ключ
- `-out server.crt` — сохраняет сертификат в файл
- `-days 365` — сертификат действителен 365 дней
- `-config openssl.cnf` — использует наш конфигурационный файл
- `-extensions req_ext` — применяет расширения из секции `[req_ext]`

**Ожидаемый результат:**
Команда выполнится без вывода (если всё успешно).

**Проверьте файл:**
```bash
ls -lh server.crt
# -rw-r--r-- 1 user user 1.4K ... server.crt
```

## ✅ Шаг 6: Проверка сертификата

Убедитесь, что сертификат создан правильно.

### Просмотр информации о сертификате

```bash
openssl x509 -in server.crt -text -noout
```

**Что вы должны увидеть:**

```
Certificate:
    Data:
        Version: 3 (0x2)
        Serial Number: ...
        Signature Algorithm: sha256WithRSAEncryption
        Issuer: C=RU, ST=Moscow, L=Moscow, O=MeetFlow, OU=Development, CN=192.168.1.100
        Validity
            Not Before: ...
            Not After : ...
        Subject: C=RU, ST=Moscow, L=Moscow, O=MeetFlow, OU=Development, CN=192.168.1.100
        ...
        X509v3 extensions:
            X509v3 Subject Alternative Name: 
                DNS:localhost, DNS:*.local, IP Address:127.0.0.1, IP Address:192.168.1.100
```

**Проверьте:**
- ✅ `Issuer` и `Subject` содержат ваш IP адрес
- ✅ `Validity` показывает срок действия 365 дней
- ✅ `Subject Alternative Name` содержит `localhost`, `*.local`, `127.0.0.1` и ваш IP

### Проверка соответствия ключа и сертификата

```bash
# Модуль ключа
openssl rsa -in server.key -modulus -noout | openssl md5

# Модуль сертификата
openssl x509 -in server.crt -modulus -noout | openssl md5
```

**Результат должен быть одинаковым!**

## 📂 Шаг 7: Структура файлов

После выполнения всех шагов в папке `ssl/` должны быть:

```
ssl/
├── server.key      # Приватный ключ (НЕ ПЕРЕДАВАТЬ!)
├── server.crt      # Сертификат (копировать на все устройства)
└── openssl.cnf     # Конфигурация (можно удалить)
```

## 📱 Шаг 9: Установка сертификата на устройствах

Поскольку сертификат самоподписанный, браузеры будут показывать предупреждение. Чтобы избежать этого, установите сертификат как доверенный на всех устройствах.

### 🪟 Windows

1. **Скопируйте файл** `ssl/server.crt` на устройство (через USB, сеть, email)

2. **Дважды кликните** по файлу `server.crt`

3. Нажмите **"Установить сертификат"**

4. Выберите **"Локальный компьютер"** (требуется администратор)

5. Выберите **"Поместить все сертификаты в следующее хранилище"**

6. Нажмите **"Обзор..."**

7. Выберите **"Доверенные корневые центры сертификации"**

8. Нажмите **"Далее"** → **"Готово"**

9. Подтвердите установку

**Альтернативный способ через PowerShell:**

```powershell
# Запустите PowerShell от имени администратора
Import-Certificate -FilePath "C:\путь\к\server.crt" -CertStoreLocation Cert:\LocalMachine\Root
```

### 🍎 macOS

1. **Скопируйте файл** `ssl/server.crt` на Mac

2. Откройте **Keychain Access** (Связка ключей):
   - Spotlight: `Cmd+Space`, введите "Keychain Access"
   - Или: Applications → Utilities → Keychain Access

3. Перетащите файл `server.crt` в раздел **"System"** (Система)

4. Введите пароль администратора

5. **Дважды кликните** по сертификату "192.168.1.100"

6. Разверните раздел **"Trust"** (Доверие)

7. В поле **"When using this certificate"** (При использовании этого сертификата) выберите:
   - **"Always Trust"** (Всегда доверять)

8. Закройте окно

9. Введите пароль администратора для подтверждения

**Альтернативный способ через терминал:**

```bash
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain server.crt
```

### 📱 iOS (iPhone/iPad)

1. **Отправьте файл** `ssl/server.crt` на устройство:
   - Email
   - AirDrop
   - iCloud Drive
   - USB

2. Откройте файл на устройстве

3. Появится сообщение **"Profile Downloaded"**

4. Перейдите в **Settings** (Настройки)

5. Нажмите **"Profile Downloaded"** (Загруженный профиль)

6. Нажмите **"Install"** (Установить)

7. Введите пароль устройства

8. Подтвердите установку

9. Перейдите в **Settings** → **General** → **About** → **Certificate Trust Settings**
   (Настройки → Основные → Об этом устройстве → Доверие сертификатам)

10. Включите переключатель для вашего сертификата

11. Подтвердите **"Continue"** (Продолжить)

### 🤖 Android

1. **Скопируйте файл** `ssl/server.crt` на устройство:
   - Email
   - USB
   - Google Drive

2. Откройте файл через файловый менеджер

3. Перейдите в **Settings** (Настройки)

4. Выберите **"Security"** (Безопасность) или **"Security & Privacy"**

5. Выберите **"Encryption & Credentials"** (Шифрование и учетные данные)

6. Выберите **"Install a certificate"** (Установить сертификат)

7. Выберите **"CA certificate"** (Сертификат CA)

8. Подтвердите установку

9. Найдите и выберите файл `server.crt`

10. Подтвердите установку

**Примечание:** Путь может отличаться в зависимости от версии Android и производителя устройства.

### 🌐 Chrome/Edge (быстрый способ без установки)

Если не хотите устанавливать сертификат:

1. Откройте `https://192.168.1.100:3000`

2. Увидите предупреждение: **"Your connection is not private"**

3. Нажмите **"Advanced"** (Дополнительно)

4. Нажмите **"Proceed to 192.168.1.100 (unsafe)"** (Перейти на сайт)

5. Камера и микрофон будут работать

**Примечание:** Этот способ работает, но предупреждение будет появляться каждый раз.

### 🦊 Firefox (быстрый способ без установки)

1. Откройте `https://192.168.1.100:3000`

2. Нажмите **"Advanced"** (Дополнительно)

3. Нажмите **"Accept the Risk and Continue"** (Принять риск и продолжить)

## 🧪 Шаг 10: Проверка работы

### Проверка в браузере

1. Откройте `https://192.168.1.100:3000`

2. Если сертификат установлен правильно:
   - ✅ Нет предупреждений о безопасности
   - ✅ В адресной строке значок замка 🔒
   - ✅ Сайт загружается нормально

3. Если видите предупреждение:
   - Проверьте, что сертификат установлен в доверенные
   - Убедитесь, что IP адрес в сертификате совпадает с адресом в URL
   - Перезапустите браузер

### Проверка камеры и микрофона

1. Зарегистрируйтесь на сайте

2. Создайте встречу

3. Разрешите доступ к камере и микрофону

4. Проверьте, что видео и аудио работают

**Если не работает:**
- Убедитесь, что используете HTTPS (не HTTP)
- Проверьте разрешения браузера для камеры и микрофона
- Перезапустите браузер

## 🔄 Обновление сертификата

Сертификат действителен **365 дней**. Перед истечением срока создайте новый:

```bash
# Перейдите в папку ssl
cd ssl

# Удалите старые файлы
rm server.key server.crt

# Повторите шаги 3-5 (генерация ключа, конфигурация, сертификат)

# Перезапустите сервер
cd ..
node server.js
```

## 🐛 Решение проблем

### Проблема: OpenSSL не найден

**Решение:**
- Linux: `sudo apt install openssl`
- macOS: `brew install openssl`
- Windows: Скачайте с https://slproweb.com/products/Win32OpenSSL.html

### Проблема: Permission denied при создании файлов

**Решение:**
```bash
# Linux/macOS
sudo mkdir ssl
sudo chown $USER:$USER ssl
cd ssl
```

### Проблема: Ошибка при генерации сертификата

**Проверьте:**
- Правильно ли указан IP адрес в `openssl.cnf`
- Есть ли права на запись в папку `ssl/`
- Не поврежден ли файл `server.key`

### Проблема: Сертификат не работает в браузере

**Проверьте:**
- IP адрес в URL совпадает с IP в сертификате
- Сертификат установлен в доверенные
- Браузер перезапущен после установки сертификата
- Используется HTTPS (не HTTP)

### Проблема: Камера/микрофон не работают

**Решение:**
- Убедитесь, что используете HTTPS
- Проверьте разрешения браузера
- Установите сертификат в доверенные
- Перезапустите браузер

## 📚 Дополнительные команды OpenSSL

### Просмотр сертификата

```bash
openssl x509 -in server.crt -text -noout
```

### Проверка срока действия

```bash
openssl x509 -in server.crt -dates -noout
```

### Проверка ключа

```bash
openssl rsa -in server.key -check -noout
```

### Экспорт в формат PKCS12 (для некоторых устройств)

```bash
openssl pkcs12 -export -out certificate.p12 -inkey server.key -in server.crt
```

### Конвертация в PEM

```bash
openssl x509 -in server.crt -out server.pem -outform PEM
```
